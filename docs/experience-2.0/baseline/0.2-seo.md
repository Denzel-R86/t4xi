# 0.2 — SEO-snapshot (Baseline)

Vastgelegd op 2026-10-06, op `origin/main` 6f9bc52 (+ plandocs b065c14).
Doel: een test die **faalt bij verlies** van een sitemap-URL, `<title>`, canonical,
hreflang-alternates of `<h1>`. Vangnet voor fase 1–8, expliciet voor de SEO-rollout in fase 7.

## Wat er wordt vastgelegd

Per URL uit `/sitemap.xml`:

| Veld | Bron in de pagina | Regel |
|---|---|---|
| HTTP-status (+ `Location`) | response, `redirect: manual` | elke wijziging = fout |
| sitemap-hreflang | `<xhtml:link rel=alternate>` in de sitemap | verlies/wijziging = fout, nieuw = waarschuwing |
| `<title>` (+ aantal) | document-`<title>` (SVG-titels uitgesloten) | verlies/wijziging = fout, extra = waarschuwing |
| canonical (+ aantal) | `<link rel=canonical>` | verlies/wijziging = fout, tweede canonical = fout |
| hreflang | `<link rel=alternate hreflang>` | verlies/wijziging = fout, nieuw = waarschuwing |
| meta robots | `<meta name=robots>` | wordt `noindex` = fout, andere wijziging = waarschuwing |
| `<h1>` (tekst + aantal) | alle `<h1>`'s, tekst genormaliseerd | verdwenen/gewijzigd = fout, extra = waarschuwing |

Plus `robots.txt`: verdwenen regel = fout, nieuwe regel = waarschuwing. Een URL die uit de
sitemap verdwijnt = fout; een nieuwe URL = waarschuwing.

**Waarom wijziging ook fout is (niet alleen verlies):** voor een zoekmachine is een andere
title/canonical/h1 het verlies van de oude. Bewuste wijzigingen gaan via
`npm run seo:snapshot -- --update` in dezelfde PR; de fixture-diff is dan het reviewbare bewijs.

## Hoe de sitemap en metadata ontstaan

- `app/sitemap.ts` is **volledig statisch**: 20 paden uit `TRANSLATABLE` (12 vaste pagina's +
  `AIRPORT_ROUTE_PATHS` (6) + `LOCAL_HUB_PATHS` (2) uit `i18n/routing.ts`) × 2 locales = **40 URL's**.
  Geen Sanity- of Supabase-afhankelijke URL's in de sitemap.
- Metadata loopt centraal via `lib/seo-locale.ts` (`localeMetadata`/`pageMetadata`): titel en
  omschrijving uit `messages/*.json` (namespace `seo`), canonical/hreflang uit `localeUrl()` met de
  vaste `SITE_URL` (`https://www.t4xi.nl`). Daardoor zijn ze in CI identiek aan productie.
- `[slug]`-pagina's (stadshubs, Schiphol-routes) halen titel/h1 uit `lib/seo-stad-hubs.ts` en
  `lib/seo-steden.ts` (code). De tarieven in die pagina's komen uit Supabase, maar zitten niet in
  de snapshot; zonder Supabase-env renderen de pagina's gewoon (zonder bedragen).

## Bestanden

- `scripts/seo-snapshot.ts` — CLI; start zelf `next start` (poort 3102, `APP_ENV=development`)
  tenzij `--base` is gegeven.
- `scripts/seo-snapshot/extract.ts` — pure extractie (sitemap, head, h1), geen dependency.
- `scripts/seo-snapshot/compare.ts` — snapshotmodel, vergelijkregels, `CMS_DEPENDENT`.
- `scripts/seo-snapshot/compare.test.ts` — 10 unit-tests (elke verliessoort faalt aantoonbaar).
- `docs/experience-2.0/baseline/seo-snapshot.json` — **de fixture waartegen CI toetst** (lokale build).
- `docs/experience-2.0/baseline/seo-snapshot.production.json` — productie-snapshot, zelfde formaat.

## Gebruik

```bash
APP_ENV=development npm run build
npm run seo:snapshot                    # vergelijk met de fixture (exit 1 bij verlies)
npm run seo:snapshot -- --update        # fixture bewust verversen
npm run seo:snapshot -- --base https://www.t4xi.nl   # productie tegen dezelfde fixture
npm run seo:snapshot -- --base https://www.t4xi.nl \
  --fixture docs/experience-2.0/baseline/seo-snapshot.production.json --update
```

Productie wordt alleen met read-only GET's benaderd (42 requests: sitemap, robots, 40 pagina's;
max. 2 tegelijk, eigen User-Agent `T4XI-SEO-Snapshot/1.0`).

## CI

In `.github/workflows/ci.yml` (job `quality`, zonder secrets, `APP_ENV=development`):

1. na `npm test`: `node --import tsx --test "scripts/seo-snapshot/*.test.ts"` (< 1 s);
2. na `npm run build`: `npm run seo:snapshot` — start `next start` op de gebouwde app, haalt
   42 URL's (sitemap, robots, 40 pagina's) op en vergelijkt. Lokaal gemeten: **~1,2 s** inclusief serverstart (de build zelf ~60 s
   bestond al). Geen extra install, geen nieuwe dependency.

## Bewijs: de test faalt bij verlies

Tijdelijke wijziging (niet gecommit, daarna teruggedraaid en opnieuw gebouwd → weer groen):
`seo.overOnsTitle` leeg in `messages/nl.json`, de `<h1>` in `ContactSection` → `<h2>`,
`/dagtochten` uit `app/sitemap.ts`. Uitvoer:

```
✗ /over-ons: <title> gewijzigd: "Over ons — T4XI" → "— T4XI"
✗ /dagtochten: URL verdwenen uit sitemap.xml
✗ /en/dagtochten: URL verdwenen uit sitemap.xml
✗ /contact: <h1> verdwenen of gewijzigd: "Neem contact op" (nu: [])
✗ /en/contact: <h1> verdwenen of gewijzigd: "Get in touch" (nu: [])

✗ SEO-snapshot FAALT: 38 URL's gecontroleerd tegen 40 … — 5 fout(en), 0 waarschuwing(en)
exit 1
```

Canonical-, hreflang-, noindex-, status- en robots.txt-verlies zijn afgedekt in de unit-tests.

## Wat níét in CI wordt gedekt (en waarom)

1. **CMS-teksten op `/diensten` en `/en/diensten`.** Titel (`generateMetadata`) en h1
   (`ServicesSection`) komen uit Sanity (`loadCmsServicesPage`) met een codefallback. In de
   lokale/CI-build viel de loader terug op de fallback (buildlog: `[cms] dienstencontent niet
   beschikbaar; codefallback actief`; vermoedelijk door het ontbrekende `SANITY_API_READ_TOKEN`),
   productie toont de CMS-titel. Omdat een redacteur dit zonder deploy kan wijzigen, toetst CI
   hier alleen **aanwezigheid en aantal** (`CMS_DEPENDENT` in `compare.ts`), niet de tekst.
   De exacte productietekst staat in `seo-snapshot.production.json` en wordt gecontroleerd met de
   handmatige productierun (hieronder).
2. **Productie zelf.** CI toetst de build, niet wat Vercel serveert (redirects, edge-config,
   CMS). Daarvoor: `npm run seo:snapshot -- --base https://www.t4xi.nl --fixture
   docs/experience-2.0/baseline/seo-snapshot.production.json` — handmatig na elke fase-7-batch en
   na elke CMS-wijziging aan SEO-velden. Een nachtelijke scheduled workflow hiervoor is bewust niet
   toegevoegd (vraagt een besluit over geplande verzoeken naar productie); voorstel voor na de gate.
3. **Pagina's buiten de sitemap** (bijv. `/dashboard/invoices`, `/klant`): niet in scope; die zijn
   via `robots.txt` uitgesloten en via `proxy.ts` 404/afgeschermd.
4. **Meta description, Open Graph, JSON-LD**: niet gevraagd voor 0.2 en niet in de snapshot.
5. **Prijzen op routepagina's** (Supabase): geen SEO-signaal in deze snapshot; zonder env tonen
   de pagina's geen bedrag.

## Findings

Niets hiervan is gerepareerd (regel: baseline-PR's repareren geen productgedrag). Ernst: H/M/L.

- **F1 (M) — `/diensten`-titel degradeert stil bij CMS-uitval.** Productie:
  "Premium taxi- en chauffeursdiensten — T4XI"; fallback (CI, of als Sanity >3 s niet antwoordt):
  "Diensten — T4XI". De pagina is SSG; een build tijdens een Sanity-storing bevriest de zwakke
  titel tot de volgende build. Overweeg de fallback-titel in `messages` gelijk te trekken met de CMS-titel.
- **F2 (M) — EN `/en/tarieven`-h1 matcht de zoekintentie niet.** Title: "Calculate taxi fare —
  get your fixed price instantly"; h1: "Arrive composed. Your journey begins with certainty."
  (NL-h1 is wél inhoudelijk: "Taxitarieven zonder verrassingen."). /tarieven is de pagina met
  81% van de impressies (GSC-nulmeting); geen "fare"/"taxi" in de EN-h1.
- **F3 (L) — Homepage: canonical/hreflang zonder slash, sitemap met slash.** Pagina:
  `https://www.t4xi.nl` (en `x-default`/`nl-NL` idem op `/en`); sitemap-`<loc>` en
  sitemap-alternates: `https://www.t4xi.nl/`. Volgens de URL-spec identiek voor de root, dus
  geen indexatierisico, wel inconsistent. Alle andere 38 URL's: canonical == sitemap-`<loc>`.
- **F4 (L) — Generieke, korte titels zonder dienst/plaats.** O.a. "Over ons — T4XI",
  "Dagtochten — T4XI", "Boek een rit — T4XI", "Mobiliteitsproducten — T4XI", "Contact — T4XI"
  (NL en EN identiek). Niet fout, wel gemiste relevantie; kandidaat voor fase 7.
- **F5 (L) — `/nl/*` redirect met 307 (tijdelijk)** naar het pad zonder prefix
  (`/nl/tarieven` → 307 → `/tarieven`); apex en http geven correct 308. Next-intl-standaard; een
  permanente 308 zou consistenter zijn als `/nl/`-links ooit extern circuleren.
- **F6 (info) — Sitemap zonder `<lastmod>`.** Alle 40 entries hebben alleen `changefreq` en
  `priority` (beide door Google genegeerd). Geen fout.

Geen bevindingen op: 404's in de sitemap (0), dubbele h1 (0), ontbrekende canonical (0),
hreflang-gaten (0, alle paren wederkerig), noindex op sitemap-URL's (0), dubbele titles binnen
één taal (0).
