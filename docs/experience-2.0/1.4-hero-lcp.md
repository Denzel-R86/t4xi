## Wat er verandert

Hero (`app/[locale]/page.tsx`, Arrival) krijgt de §5-cascade, puur CSS in
`components/horizon/horizon.css` (`.hz-hero-*`, `@keyframes hz-hero-rise`):

| Deel | Klasse | Delay | Duur | Start |
|---|---|---|---|---|
| Eyebrow (kicker) | `.hz-hero-eyebrow` | 100ms | `--hz-composed` (700) | opacity 0, 12px |
| Kopregel 1 | `.hz-hero-line1` | 180ms | `--hz-composed` | **opacity .01**, 20px |
| Kopregel 2 | `.hz-hero-line2` | 280ms | `--hz-composed` | **opacity .01**, 20px |
| Subcopy | `.hz-hero-sub` | 430ms | `--hz-ui` (280) | opacity 0, 12px |
| Boekingszin | `.hz-hero-booking` | 550ms | `--hz-ui` | opacity 0, 12px; `:focus-within` → direct 1 |
| Trustline | `.hz-hero-trust` | 700ms | `--hz-ui` | opacity 0, 12px |

Alles is uiterlijk na 980ms klaar (< 1s). Alleen `opacity` en `transform`; de lay-out
staat vanaf de eerste paint vast (CLS blijft 0).

**Poort `scripting: enabled` in plaats van `html.js`.** §5 zegt "alleen `html.js`". In de
App Router voert de Next-runtime `<Script strategy="beforeInteractive">` uit via
`self.__next_s` (`node_modules/next/dist/client/script.js`), dus `html.js` komt pas ná de
eerste paint. Een cascade onder `html.js` zou de hero eerst tonen en daarna opnieuw van
opacity 0 laten opkomen (flits, en een herstart van de LCP-kandidaat). De media feature
`scripting: enabled` geldt al bij het parsen en heeft dezelfde bedoeling (zonder JS:
niets). Een browser zonder deze feature krijgt geen animatie. De animatie zelf heeft geen
JS nodig om te eindigen, dus er is geen inhoud die op hydratie wacht.

**LCP-keuze.** De kopregels starten op opacity .01 en niet op 0 (§5 LCP-regel): Chrome
telt een element met opacity 0 niet als LCP-kandidaat en zou LCP pas registreren als de
fade begint (≥ 180ms later). Met .01 wordt de h1 bij de eerste paint geregistreerd. Of
het LCP-element op `/` de h1 of de hero-afbeelding is, legt de meting vast (LCP-element
per run, F-10).

**Reduced motion.** `@media (prefers-reduced-motion: reduce)` zet `animation: none` op alle
zes klassen; de motion-regels staan bovendien alleen in de `no-preference`-query. Zonder
animatie blijven de kopregels `inline` (geen `inline-block`), dus pixel-gelijk aan vóór
1.4. Bewaakt in `lib/design/hero-cascade.test.ts`.
